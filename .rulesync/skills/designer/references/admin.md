# Admin and frequent operational work

Start from the operator's sequence: find, compare, select, act, verify and recover. Preserve task position and context across filtering, sorting, pagination, side panels and asynchronous updates. Density is useful when it reduces work without obscuring meaning or interaction targets.

Design with realistic scale: long names, missing values, large numbers, many rows, permission differences and delayed data. Keep table headers, units, sorting state and selection scope explicit. A missing value is not zero; a stale metric is not current. For bulk actions communicate exactly which items will change, partial failures and a safe recovery path.

Use existing shortcuts, focus patterns, sticky regions and component variants. Make keyboard operation efficient, but do not remove understandable feedback solely because a keyboard triggered it. Offer a non-drag way to perform dragging functions when relevant. Do not shrink every hit area to fit more rows or hide primary actions behind hover.

Favor immediate input and unobtrusive state feedback. Animate spatial changes only when they help orientation; repeated decorative entrances usually add friction. Status must remain understandable without color or animation. Distinguish blocked actions, missing permissions and temporary unavailability with useful explanations.

Verify the real work sequence, not a balanced empty dashboard: long-content layout, narrow mode, overflow, focused rows, selection after data changes, error recovery and focus after dismissal. A table may need two-dimensional scrolling; its surrounding controls and reading content should still adapt.
