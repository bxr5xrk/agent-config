# Refactoring UI foundations

The user's supplied Refactoring UI book complements interaction-oriented skills with visual composition. Apply the reasoning to the project's actual content, not the dated appearance of an example.

- Start with a useful feature and its content before designing a generic application shell (pp. 7–13).
- Establish a fitting personality and constrained token choices; do not pick independent colors/sizes for every element (pp. 17–28).
- Use visual hierarchy through grouping, weight, contrast and position. De-emphasizing competing content can be more effective than enlarging the primary element (pp. 30–54).
- Let spacing explain groups and choose useful content widths. Dense operational surfaces and public storytelling need different rhythms (pp. 56–86).
- Judge type at actual size, with real line lengths, mixed-size baselines and narrow-screen wrapping (pp. 88–116).
- Preserve readable contrast across surface colors and real image crops. Treat depth as a relationship between elements, not mandatory ornament (pp. 119–190).
- Design meaningful empty and recovery states alongside the populated screen (pp. 192–214).

The book's advice to omit redundant data labels explicitly excludes form labels. Its discussion of button semantics concerns visual priority, not semantic HTML. Fixed palette counts, HSL preference and particular fonts are heuristics. For current contrast thresholds use the [visual QA reference](visual-qa.md), not the book's approximate 18px shorthand.

Source: Adam Wathan and Steve Schoger, *Refactoring UI*, from a user-provided local copy. The skill remains usable without the PDF; reopen relevant pages only for a specific visual-source question.
