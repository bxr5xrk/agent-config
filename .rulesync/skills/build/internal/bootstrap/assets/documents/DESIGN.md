# Design contract

## Options and selection
Visual artifact links for explored options when needed; requested count and comparison; source URLs; round ID and selected IDs or exact user override; combination rules and rejected/superseded history.

## Product identity
Link BRAND.md when applicable: approved name/identity, desired impression, reference/anti-reference reasons and content voice.

## Tokens
Actual semantic colors, type scale, spacing, widths, radius, elevation and motion; contrast evidence and canonical code token path. Reconcile with BRAND.md.

## Components and states
Scope-specific kit; responsive behavior; default/hover/focus/active/disabled/pending/error/empty/success.

## Brand assets
Logo/wordmark, favicon, OG when public; source/licensing and export paths.

## Verification
Reference comparison plus actual browser states, mobile and keyboard evidence.

## Landing direction and motion, when applicable
First-screen composition, focal idea, content/section rhythm, shortlisted motion previews and selected behavior. Record triggers, interruption, touch/mobile and reduced/static alternatives; preserve the visible initial message and CTA. See LANDING-REVIEW.md for scoped evidence.

## Component provenance
Source/item/version, license/access, selected primitive base, dependencies and adaptations to the shared tokens. Demo claims/assets/actions must be reconciled with the real product.
