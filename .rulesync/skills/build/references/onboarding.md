# New projects and existing onboarding records

- **New idea:** brainstorm resolves consequential unknowns and records the brief. Build continues when implementation is authorized; the user does not copy the conversation into a second questionnaire.
- **New directory:** use [internal bootstrap](../internal/bootstrap/ROLE.md) with the [adopted defaults](defaults.md), agreed scope and existing or delegated design direction. Add only the required web/API profile. Designer owns [naming and identity](../../designer/references/branding.md) when needed.
- **Existing project:** reuse its stack and canonical brief/design/brand/analytics records, including older `docs/onboarding` and state files. Reconcile approved decisions against the current code before editing. Do not run the generator over an existing project.
- **Later change:** build or the relevant specialist reads the affected context and proceeds. Reopen only the decision invalidated by the change.

Brainstorm owns discovery, build owns integration and designer owns creative direction. Internal bootstrap replaces the former standalone onboarding workflow.
