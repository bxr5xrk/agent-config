# Research that changes decisions

Start with the user's own problem and reference material. Research relevant official API/platform constraints, primary technical documentation, demonstrated production patterns, competing product flows and actual user feedback. Distinguish documented behavior, observed product behavior, vendor claims, anecdotes and your inference.

Record only decision-bearing findings: source URL, access date, relevant version, finding, implication and remaining uncertainty. Inspect representative real interfaces rather than treating home-page marketing as product proof. For code/skills inspect canonical source and executable validation, not stars, persona names, generated bundles or output-length scores.

When useful, propose an inexpensive reversible prototype that resolves a named uncertainty. Define what observation would reject the preferred approach before building it. A polished mockup does not validate demand or production architecture.

For uncertain logic, expose the relevant states, actions and awkward transitions in a small executable example. For a visual question, ask designer for an actual comparable surface using realistic content and neighboring UI. Keep prototypes isolated from production behavior; carry the decision and useful evidence forward, then implement under normal verification. Do not treat throwaway code as production-ready merely because the experiment worked.

Delegate a bounded source question when independent reading can proceed alongside useful work. Pass the decision it must inform, required primary sources and expected evidence; inspect the result before relying on it. Simple lookups need no extra agent.

For public discovery surfaces, identify the audience's search intents, differentiating content, distribution channels and measurable first conversion. For internal tools, investigate task frequency, data density, permissions and recovery. Do not add marketing SEO to a private workflow.

Keep a short alternatives table when a choice matters: option, why it fits, what it gives up, and evidence. Make a recommendation. Defer details that do not affect the first release instead of expanding the scope through research.
