# Project context

Read applicable project instructions first, then only the project documents and code needed for the current decision. Separate explicit user decisions, observed implementation facts, and unresolved choices. Newer project decisions override reusable preferences within that project.

Keep the original requested outcome, exclusions, language and authorization in the brief. A diagnosis-only request stays read-only; an implementation request may authorize scoped edits and verification. Never treat a proposed design, inferred requirement or unverified integration as accepted fact.

Project names, brand details, tenant logic and provider-specific behavior stay in project documents. Only portable methods and explicitly global preferences belong in this skill.
