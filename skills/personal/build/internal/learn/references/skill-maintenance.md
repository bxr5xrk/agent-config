# Maintain small, reachable instructions

Use when an approved change requires editing specialist instructions. Keep one authoritative statement per rule. Put always-needed actions and observable completion criteria in the entrypoint; put conditional knowledge in a focused reference with an explicit trigger at its caller. A hidden reference without a working pointer does not reliably change behavior.

Before adding text, determine whether the failure came from missing guidance, an unclear trigger or an existing instruction being ignored. Tighten the relevant pointer or rule instead of repeating it in every specialist. Leave discoverable versions, commands and file structure to current environment inspection; retain the non-obvious reason and adopted convention.

Prune duplicate, stale and irrelevant guidance by checking the behaviors it is meant to change. Shorter prose alone is not evidence of improvement. Use the [evaluation procedure](evaluation.md) with an unseen applicable case and a counterexample, verify relative links and installed discovery after packaging changes, and preserve actual failures for later repair.

Keep reviewed source updates separate from automatic lesson candidates. User-authorized skill maintenance can proceed in its scope; corrections captured during product work still follow [curation](curation.md) and batch approval before becoming global instructions. Preserve approved conventions when upstream changes its default behavior.
