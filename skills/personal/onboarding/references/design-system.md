# From selected direction to reusable UI

For `product_brand`, write DESIGN.md before broad UI implementation. Translate the selected option into semantic CSS variables: canvas/surface, primary/secondary text, border, accent/on-accent, focus, danger/success/warning; spacing, content width, breakpoints, radii, shadows, type scale, motion duration/easing. Show actual values and their contrast checks. Map these variables into Tailwind and shadcn's tokens; do not maintain two independent palettes. For `lightweight_site`, keep only the local tokens and component decisions needed by the implemented page; do not create a broad system for its own sake.

Minimum kit is scope-dependent: button/link, text field + label/help/error, checkbox/select as needed, alert/toast, spinner/skeleton, empty/error state, navigation, dialog only if the flow needs it, table/list if data calls for one. For every included control show default, hover, focus-visible, active, disabled, pending, error and success where meaningful. Use semantic elements. Decorative card grids are not a required kit primitive.

Create a component preview route or Storybook only if worthwhile. The starter's `/ui` is a technical behavior sample, not the final design system; replace its tokens and expand its scope from the selected design. Build app screens from these components, then inspect them at narrow/wide widths with real-length content.

Brand deliverables apply the approved BRAND.md: product name/wordmark, icon/logo direction aligned with the selected visual identity, light/dark or one-color variants where relevant, favicon, and public OG image. Prefer vector source for simple original geometric marks; use image_gen for requested raster creation/edits. Inspect tiny favicon size and legibility, transparency/background, and licensing. Don't invent trademark clearance. Existing approved logos must be preserved.

Visual guardrails: a recognizable hierarchy, useful contrast, deliberate content density, and one product-specific distinguishing idea. No automatic gradient hero, identical bento layout, unnecessary blobs, ornamental badges or arbitrary all-caps labels. These are not blanket bans: use an element if it serves the selected direction. Do not confuse visual novelty with task efficiency.
