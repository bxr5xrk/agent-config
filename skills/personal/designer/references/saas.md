# SaaS product surfaces

Map the user's core job and the next useful action in each state. An authenticated application, its pricing page and its internal admin may need different profiles. Choose by surface and frequency, not by the SaaS label.

For B2B SaaS marketing and product surfaces, default to a credible software-product language: clear hierarchy, purposeful whitespace, real product evidence, and a visible explanation of the core workflow or outcome. Do not substitute ornamental, miltech, travel/lifestyle, newspaper/editorial, or game-like art direction for product positioning unless the brief or approved references call for it. This is a domain heuristic, not a universal style ban.

Keep navigation, terminology, component behavior and saved work predictable. Design the first-use path around real progress; distinguish onboarding help from routine work. Empty states explain what is missing and offer the action that can actually create it.

Specify the affected loading, success, empty, validation, error, permission and recovery states. Preserve entered data on failure. Make asynchronous changes truthful: pending is not saved, an optimistic change needs reconciliation, and a retry should not silently duplicate an action. Coordinate these guarantees with the implementation owner.

Use progressive disclosure where complexity is conditional; avoid hiding information needed to choose. Write labels and errors in the product's language. Include realistic international text lengths, currency/date conventions and data volume where the project requires them.

Use motion for orientation and meaningful feedback, with reduced/static equivalents. Keep frequently repeated controls responsive. Match polish to the product's personality without turning every interaction into an event.

Verify a complete relevant journey from entry to persisted result, including failure and return. For forms check visible labels, error association and focus; for overlays check opening, dismissal, keyboard containment where modal, and focus return. A visually successful state must correspond to the real product state.
